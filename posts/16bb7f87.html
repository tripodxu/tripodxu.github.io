让一万个人格读同一段话

发表于2026-09-28|更新于2026-10-31|项目
|总字数:1.5k|阅读时长:5分钟|浏览量:

本文按 git 提交历史回填，日期是项目第一个提交那天。

2026 年 9 月 28 日，第一个提交是「Step 1 baseline - working mock pipeline (worker + D1 + static frontend)」。第一天 44 次提交，整条链路就跑通了——当然，是假数据。

时间线

阶段 日期 干了什么
1 09-28 mock 全链路、多版本、追问与定价阶梯
2 09-29 ~ 09-30 收波原子性、地形缓存、地图传播层
3 10-01 上线：退役限额与预算闸，改 BYOK
4 10-02 随机基线实验、六色墨水拆两版
5 10-06 ~ 10-07 日闸补回、增量快照、429 与客户端退避
6 10-18 ~ 10-25 报告渲染、CSR 邻接、两颗地雷

第一天：先跑通假的

44 次提交里，最重要的不是引擎，是数据形状：versions 表加 follow_up 和 prices 两列，每篇帖子可以有多版本（POST /api/version，v 参数贯穿 batch / wave / post）。

为什么第一天就把版本做进去？因为「改一版再发一次」是这个产品的核心用法。如果数据结构里没有版本，后面所有对比功能都得靠 hacks。

追问阶段也在这天落地：闲置帖问「买家最常问什么」，商品帖算价格需求曲线。

第二、三天：原子性

09-29 修了三处并发问题，都跟「收波」有关：

  • 空波闸门在 claim 之后必须关闭，否则同一波会被重复认领；
  • versions.plan.answered 的批量认领要原子；
  • 条件回滚不能把别人的认领一起擦掉。

这类 bug 在单机测试里永远不出现，只有真有人在页面上点才炸。

09-30 做了两件「省钱」的事：Worker 侧按 post.v 缓存地形结果（冻结版本重复查看不重算置换检验）；地图加传播层与重播——每格显示它在第几波被点亮，零新增模型调用。

上线：先砍掉自己的兜底

10-01 是上线日，也是这个项目最反常的一个决定：退役限额与预算闸，站点不提供任何 key，真实检查一律走访客 BYOK。

理由很实在：站方垫钱，就会不自觉地把产品做成「省 token」的样子——少问几个人、少跑一波、报告少算一档。而 BYOK 之后，成本和体验的取舍交回给使用者，产品只需要对结果负责。

把「不确定」做成功能

10-02 有一轮我很喜欢的工作：随机基线实验。

起因是个反复出现的疑问——为什么好几次实验都停在第一波，只有几百人？不是人数上限（第一波 600 是写死的），也不是抽样噪声。根因是续传阈值 GLAD_ENOUGH = 0.1 低于随机基线：如果从 listing 的反应表里均匀抽，tone 的均值是 +0.167。也就是说，这条线比掷骰子还松。

于是做了三臂探针：A 真实 Jev 原样跑；B 纯随机抽反应（不花钱）；C 洗掉形状（每人拿全波平均分布，仍问 Jev）。同一颗种子、同一批波、Jev 的答案三臂共用——不然同一份答案要问三遍，成本 ×3。

结果很扎心：随机臂四波 mood 恒在 +0.13 ~ +0.19，四波全过、传遍一万人。真实 Jev 的咖啡馆帖第 1 波 +0.005（z = −5.76）直接停，iPhone 帖 +0.102（z = −2.32）居然过了闸。

更有意思的是结论的转向：Jev 的价值不是「让它传」——随机传得更彻底；它的价值是把没人要的文本判死在第一波。三段文本随机都给一万人四波，Jev 给出 600 / 600 / 2100 的区分。

那一轮最终没有改阈值（改阈值需要更多真实样本标定），只做了一件事：把随机基线交给读者看。报告新增一节「和纯随机比，谁更想要它」，逐波给 z 条和一句人话结论；z ≤ −2 时必须明确写「这是真答案，不是没读出来」。

同一天还有 R30：六色反应墨水分「地图版」和「面版」两套色——因为浅色主题下，图表线条此前是隐形的。这种 bug 不做深色/浅色双截图，永远发现不了。

10-06 ~ 10-07：补回闸门，撞上 429

拆闸拆过头了：钱包是死了，D1 的日写入配额还在裸奔。10-06 把每 IP 日闸补回来（/api/check 和 /api/version 双路、环回豁免），并把收波从「每波读一万行」改成增量快照。

默认通道原本想用 OpenCode Zen 的免费档，结果发现：Zen 对 Cloudflare Worker 的共享出口持续 429，按 IP 判，和 key 无关。

浏览器直发也不行，CORS 挡死；从访客 IP 发也不行。最后落成两条：站方默认走匿名免费档（能通就通），以及客户端在 429 / 409 / 网络错误时原地指数退避。

这天还有个副产品：加了第三条 BYOK 通道，请求形状和 TypeSafe 一致，但响应没有 usage 对象，token 只能估。

最后：两颗从没被渲染过的地雷

10-25 的提交信息很直白：「报告从没被完整渲染过的两颗地雷」。

  • 十档空档时 lift = NaN，过 JSON 变成 null，整份报告直接 500；
  • 图例组件自某个版本起就坏了，但因为平时只走示例回放，没人看见。

同一天把地形置换检验的邻接表折成 CSR、值场紧凑排布，全城地形从 9–10ms 降到 8ms，读数逐位相同。

还有一件很产品的事：发帖框加了「试一句」样例、字数计、商品定价阶梯、Ctrl+Enter 提交。一个小镇最需要的不是复杂的分析，是先有人愿意写下第一句话。

回头看

146 次提交里，真正跟模型打交道的不到五分之一。剩下的是并发、缓存、限额、渲染和文案。

一万个人格不是重点。重点是让写作者看见：这一万人的反应，到底是成片的，还是零散的。
