上线第一周都在修 CI：一间临时邮局的两个月

发表于2026-09-19|更新于2026-10-31|项目
|总字数:1.3k|阅读时长:4分钟|浏览量:

先给结论：**在一个只有三十秒耐心的产品里，工程价值几乎不体现在功能上。**它体现在两件事：用户有没有看见那个错误，以及一个人的凭据能不能碰到另一个人的东西。

这个临时邮箱 143 次提交，真正算「加功能」的不到一成。剩下的都在这两件事上。

一、第一天不写业务，只修发布

开工第一天 11 次提交，几乎没有一行业务代码，全在跟 CI 较劲：Pages 部署必挂、参数传递不对；怀疑 Token 权限，加 wrangler whoami 身份探针；还是 “No access”，再加一层权限诊断。

这类活很没成就感，但它决定后面两个月敢不敢直接推 main。发布链路不通的时候，所有「快速迭代」的说法都是假的——你只是把验证成本从 CI 挪到了自己身上。

第二天的决定更能说明这个项目的取舍：发信功能按文档启用了，新地址默认 20 条余额，当天又关掉。理由是发信是开放中继的风险面，收信才是产品核心——先把危险的部分关掉。

二、一天 44 次提交，全是「让它别出错」

09-22 是转折点，44 次提交没有一次是加功能：

  • 流水线异常隔离：一封坏信不能拖垮整批；
  • Message-ID 去重（没有它，同一封信会在列表里反复出现）；
  • 错误消息脱敏；
  • 三处搜索调用点统一成一个 buildMailSearchPattern，长度限制收口——之前三处各写各的，限制都不一样。

最值得记的是匿名额度的口径。原来是按出口 IP 计数，结果用户换个网络额度就重置了，而同一个出口的多个人又能互相蹭。改成「指纹优先 + D1 计数优先」之后，这两种漂移才被同时堵住。

额度算错和额度被绕开，是两个不同的问题，用同一个计数器解决不了。

三、两个静默失效

这个项目最贵的 bug 都不报错。

其一，错误弹窗被弹窗自己盖住。 用户实测反馈「点了没反应」。查下来 .toast 的 z-index: 1001 小于 .modal-veil 的 1002——错误其实弹了，全程被遮罩压着。代码没错，逻辑没错，用户就是看不见。

其二，补丁只写了一半。 有一条提交信息是「补上 pruneDeadMailboxes 函数定义（上次 patch 写回前中断导致只有调用没有定义）」。代码能通过 lint，运行时才炸。

这两件事指向同一个结论：**门禁通过不等于功能生效。**前者需要的是「错误必须可见」这类产品级约束，后者需要的是「写入必须原子」这类工具级约束，两者都不是加测试能自动获得的。

四、上游把两种失败返回成同一个状态码

09-26 是最难的一天。上游把「会话的人机验证过期」和「创建频率超限」都返回 403 need_turnstile。而本地的处理逻辑是：读路径遇到 428 会退休会话，创建路径却一律把它放回 free 池。结果是死会话永生——每次建箱都认领它，再 403，再被报成「限流」。

第一版判据是「看 bootstrap 是否成功」：页面能开但创建被拒 = 真限流；连引导页都拒 = 会话已死。这个判据错了，因为真上游的首页无论会话死活都返回 200，探针永远触发不了。

第二次才根治，方案是两个与 provider 无关的信号：create 403 连续计数（3 次且跨越 120 秒才退休），加 cron 每 5 分钟对 free 会话做 inbox 探活。

教训不在具体判据，在判据的来源：凡是拿「上游的某个页面能不能打开」当健康信号，就等于把判据外包给了一个不承诺语义的接口。

五、越权是一个动作，不是一个漏洞

09-23 到 09-25 做的是权限语义的收口：api_keys.scope 分家（v1 与 v2 密钥互拒）；/v1 的 mailbox token 增加 API key 归属校验——之前 A 的 key 能访问 B 的邮箱；凭据恢复改成一次性 token（tmr1），短期有效、用一次即废。

这类问题的共性是：权限系统里，「能查到」和「该查到」是两个判断，而代码通常只实现了前者。

代价与局限

发信功能被砍掉了，而且没有回来的时间表。 这是主动放弃：开放中继的风险面大于它带来的功能价值。代价是这个产品永远只能收、不能回。

安全审计拖到了一个月后。 09-27 之后停了一个月，10-24 回来一口气 19 个提交补安全与并发：webhook 常量时间比较、/v1 幂等重放、/v2 的 cred_version CAS、发信显示名的 CRLF 剥离。这些本该在功能上线前做——它们是欠账，不是迭代。

「少做功能」与「没出事故」之间没有因果证据。 143 次提交里功能确实少，事故也确实少，但这是选择的结果还是运气，本文给不出答案：样本只有一个产品，也没有对照。
